## 保存与核对约定

- `source-pdfs/` 保存上传 PDF 的原样副本，不修改原文件；每年 JSON 的 `sourceSha256` 用于核对副本完整性。
- `reading-a/<年份>.json` 是本批结构化源资料，`sourcePages` 指向原卷具体页码，选项数组依次为 A、B、C、D。
- `source-answer-images/` 保存收到的答案照片原样副本；`answer-keys-pending/` 保存 2010–2024 阅读 A 的答案字母。这些待完善答案不会被现有构建流程发布。
- 正确答案字母以收到的答案照片为来源；所有题目解析仅由 AI 生成，不从 PDF 或答案照片推断。AI 解析需完成内容校验后才能发布，并应在数据中保留 AI 来源标记。
- 使用 PDF 文字层提取，按首行缩进恢复段落、连接跨页内容；只清理页眉页脚和排版换行，不生成或推断答案。
- 双栏选项按标签恢复为 A、B、C、D 顺序。例如 2010 年第 33 题页面排列为 A/C、B/D，录入为 Tide、Crest、Colgate、Unilever，已有测试固定检查此映射。2011 年 Text 1 前的阅读说明未混入文章。
- 已检查阅读 A 页面的排版与边界，按字符序列核对原卷文字层和结构化内容，并校验每年题号 21–40、每题四选项。此核对确认与所给 PDF 一致，不代表所给 PDF 本身没有印刷错误。
- **待核对原卷疑点**：2018 年 Text 3，第 4 段（PDF 第 7 页）原文为 `convert our lives to date`，疑似 `data` 的笔误。本次保留 `date`，待用户确认后更正；不查询外部答案或自行改题。

## 后续如何继续

1. 后续补充题目翻译与解析时，以“年份 + Text 编号 + 题号”对应本批答案，勿重新创建重复题目。
2. 完整答案和解析仍走 `answer-keys/` 的既有流程；不要把待完善答案混进公开题目源或用占位内容判分。
3. `npm run build:seed` 会把本批生成成 **draft** 记录，其他题型不生成；现有 2025、2026 数据仍按原流程处理。生成 SQL 不等于已导入数据库或已部署。
4. 本地开发预览与正式发布分开：仅在 development 模式且连接独立的本地数据库时，首页和文章页可以读取草稿。可查看文章、题干和选项，试点选项不保存、不创建练习记录、不判分。生产模式或其他数据库连接继续隐藏草稿，直接访问草稿地址也不返回题目。
5. 发布前先确认答案完整，调整待发布数据的导入规则，验证判分，再按用户明确授权部署。当前导入脚本拒绝直接把 `reading-a/` 中的草稿改为已发布，避免误开放无答案题目。
6. 想录入其他题型时，从上表保存的原卷继续，不依赖聊天附件或 Downloads 中的文件。

运行 `npm run test:content` 检查数量、段落、题号、选项、PDF 与答案照片来源哈希，以及待完善答案的年份、题号和取值。`npm run test:local` 也包含此检查。

原始试卷仅保存在仓库资料目录，不在网站 `public/` 下，不会作为静态资源对外提供；是否提交到远端仓库、是否发布线上均需另行授权。
