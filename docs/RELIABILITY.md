# 作答与 AI 的维护约定

## 保存与提交

五个题型通过 `use-draft-autosave.ts` 共用防抖、退避重试、串行队列和刷新/关闭页面的未保存提醒；题型规则和接口协议仍由各业务组件维护。

- `snapshot` 只描述答案变化。计时和界面语言更新不能一直重置防抖。
- 保存调用必须进入组件自己的 mutation queue。一次失败不会阻断下一次保存。
- 提交、返回和重做先设置同步操作锁，再 `drain()` 已有队列；带上当前完整答案。
- 自动保存只对网络错误和 5xx 最多重试三次，间隔为 1、2、4 秒。401/403、409、校验错误和限流不自动重试；答案保留在当前页面。
- effect 清理只取消尚未发出的保存和重试，不假设能撤销已到服务端的写入。
- 草稿保存成功后，只更新“该次保存的快照”，不能把旧响应中的答案写回编辑器。
- React 页面按任务 ID 设置 key，避免切换年份后复用上一题的状态。
- `beforeunload` 保护刷新/关闭页面；应用内跳转仍须显式等待保存，不能只依赖浏览器事件。

阅读 B 与完形另共享 `useTaskAttempt` 和后端路由工厂，保留 attempt ID 校验和数据库并发锁。写作、翻译和阅读 A 的后端协议仍不同，不应为了减少行数删除各自的状态校验。

## AI 请求

`deepseek-client.ts` 统一模型、鉴权和 JSON 请求格式；业务接口负责评分规则、返回校验、错误提示及有针对性的格式修复。传输层不自动重试付费生成，尤其不能在超时后假定上游没有执行。

`request-review.ts` 只合并同一页面运行环境内、路径与内容完全相同的进行中请求，广播进度；成功或失败都会清理，因此允许重试。它不是跨标签页或多服务实例的幂等保证；后续若引入后台批阅任务，必须在数据库建立任务唯一性与恢复机制。

切换写作任务时使旧批阅请求失效，旧任务的返回不能更新当前任务的批阅内容。

## 依赖

保留 `uuid`：当前安装的 `tencentcloud-sdk-nodejs-common` 在 `abstract_client.js` 内调用 `require("uuid")`，但没有在 dependencies 中声明它。不能仅根据 src 中没有 import 就删除；升级 SDK 后再验证是否可去除。不修改 node_modules。

## 验证与发布

- `npm run test:unit`：保存队列、重试、取消、请求传输和纯函数。
- `npm run test:regression`：评分校验、流式进度、重复请求和 AI 异常；使用模拟响应，无付费调用。
- `npm run verify`：token、Lint、类型检查及生产构建。
- `npm run test:local`：隔离 PostgreSQL 和本地邮件上的登录、账号隔离、保存/提交/重做及继续练习。不连接生产库。

CI 使用 Node 24，运行上述检查；纯函数测试直接加载 TypeScript，因此不再使用 Node 20。更改 CI 后仍须观察远端首次执行结果，不能把本地通过当作远端已通过。

以上检查不替代浏览器中的输入、焦点、刷新和移动端验收。数据库迁移应按 deploy/README.md 执行，上线和回滚另行验证。
